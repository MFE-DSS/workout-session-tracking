Le picker lit Exercise.slug/aliases et user_program_exercise_catalog ; EKB et tables d’identité ne sont pas interchangeables. L’adaptateur n’offre que leur intersection résolue exactement et publie slug immuable + nom canonique EKB + version/source. Le serveur résout à nouveau chaque nouveau slot ou remplacement natif avant écriture ; ambigu/inconnu refusé sans fuzzy ou création d’exercice implicite. Les slots manuels historiques non résolus sont conservés : renvoyer leur identité de slot propriétaire, digest et contenu inchangé, sans les faire passer par le picker. Un changement d’ordre peut les déplacer sans changer leur contenu ; toute modification/remplacement natif du mouvement exige une nouvelle sélection canonique. Un simple renommage de programme ne doit pas bloquer ces slots. Le writer web garde son fallback texte libre déjà contractuel ; la restriction du nouveau picker natif ne lui est pas transférée. Le modèle historique conserve son exercise_name figé et sa règle ZERO FK vers EKB/catalogue : aucune FK ajoutée silencieusement. Les snapshots de noms/publications ne sont pas renommés. L’identité stable figure dans le reçu de sélection technique et sa provenance, sans devenir une nouvelle admission SCI.

## Contrat de mutation et concurrence
Proposer program-builder/1.0.0, ownerBearer serveur, no-store,404étranger=inconnu, pagination bornée et If-Match dérivé du contenu courant propriétaire. Ce digest inclut noms/ordre/prescriptions/statut/version/publications ; pas updated_at seul. Le digest est relu dans la même transaction d’écriture afin qu’un changement web soit détecté.

Une table additive program_builder_operations_v1 conserve owner/clé/digest de corps/ids résultat/provenance et reçu technique ; pas seconde copie canonique de prescription. Unique(owner,command_id), hash exact de commande. Rejeu exact rend le reçu historique, jamais une nouvelle permission ; mêmeclé/autrecorps409. Métadonnées de sélection slug/name/version associées à l’opération. Migration proposée après nutrition_manual_01, pas de backfill ni DDL startup ; downgrade peuplé refusé.

Les helpers historiques auto-commit ne doivent pas être naïvement enveloppés : proposer option interne keyword commit=True (comportement web conservé), puis orchestration commit=False dans transaction propriétaire pour arbre/reçu atomiques. Publication freeze quality et matérialisation doivent rejoindre cette transaction, sans changer formule ni conditions SCI. Échec après préparation/avant commit : aucun programme ou template partiel. Les hooks commit=False seuls ne suffisent pas : les routes web lisent et reconstruisent aussi l’arbre entier avant écriture. Tous les writers programme, web et natifs, doivent passer par le même kernel propriétaire CAS et la même sérialisation, y compris créer/quota, remplacer/renommer, valider, publier, nouveau cycle, archiver et génération existante. Les formulaires web portent le digest de la source lue ; une page antérieure au déploiement sans digest reçoit un refus de précondition et relecture, pas un écrasement. La transformation d’arbre part de la version revalidée sous lock, jamais d’un ancien objet détaché. Quota owner et collision slug sont vérifiés dans cette même section sérialisée. Les messages de conflit reprennent le rendu web existant ; si visibles, preuve SSR/gate applicable avant commit. Le kernel conserve le comportement métier web, sa saisie libre et les identités historiques. Tests obligatoires : webpage ancienne contre mutation native, deux créations au dernier emplacement quota, cycle/publication concurrents et erreur entre freeze qualité et matérialisation. Cette refactorisation est dans le nouveau scope proposé, pas autorisée par le GO MOB06.

## Migration consumers discovered during execution

The exact-head EKB sentinel and QA database/release schema pins consume the current migration/snapshot. It does not weaken DDL/FK/fingerprint checks, broaden providers or authorize any deployment/build/update. Historical PREPARE/binary receipts are not rewritten.
