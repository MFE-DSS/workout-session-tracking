# DA-06C — périmètre de preuve interactive

Direction opérateur explicite, source OPERATOR_DA06C.md. I etII rejetés. Une seule exploration, pas de vote entre variantes. Trois états d’un même espace : Lire, Acquérir, Examiner. Pas de nouvelles couleurs, primitives, API BODY, modèle, migration ou source SCI. Les contrôles du banc sont externes au produit ; aucune copie technique dans le parcours.

## Brainstorming / options / risques / choix retenu

Le workspaceII organise la lecture ; la mémoireI devient contextuelle et se trouve dans Examiner. L’acquisition remplace le contenu actif, sans graphique permanent. Choix opérateur, non une nouvelle option à arbitrer. Réutiliser interfaces BODY, commandes exactes SQLite, correction/lignées. Numérique40sp simple/30sp bilatéral avec vrais kg/cm, police plafonnée uniquement pour les chiffres. Autres textes grandissent et défilent ; commande toujours accessible. Fondu bref d’état seulement, aucune animation du clavier, du graphe ou du nombre. Respect de réduction des animations.

## Frontières et autorisation

Le mandat autorise ce spike local réversible et ses tests. Il ne vaut pas acceptation des pixels ni intégration ConnectedApp. Pas de commit UI avant décision sur le workspace complet. Le GO BODY/amendement/G1 existant n’est pas redemandé. Aucun APK/OTA/déploiement/donnée réelle. La source BODY récupérée reste un candidat incomplet ; aucun résultat global anticipé.

## Fichiers possédés

Ce dossier de prototype durable, son serveur et ses données de test isolées ; annexe DA06C_VISUAL_SCOPE.md du change BODY existant. Aucun fichier source produit mobile modifié avant acceptation, aucune baseline modifiée. Les quatre reçus précédents et les planches rejetées restent conservés.

## Sortie

Un seul prototype et un board bref : mêmes tâches que DA06B, sources/dates/unités, inconnus, confirmation/readback, correction/original, bilatéral, annulation, échec réseau/réponse perdue et reprise. Recette agent distincte d’un essai opérateur et d’une acceptation physique. La décision humaine porte sur l’ensemble Lire→Acquérir→Examiner.

## Précision opérateur après rejet — évolution du cadre

Le rejet vise le cadre et la qualité de DA, notamment les angles carrés, plutôt qu’une interaction métier défaillante. L’opérateur demande de dépasser les premières petites pièces visuelles. Le spike explore donc un successeur BODY de Frame C : enveloppe continue, fenêtre intégrée et commandes cohérentes. FRAME_EVOLUTION_SCOPE.md dans le dossier durable décrit cette correction. La restriction antérieure « pas de nouvelles primitives » ne bloque plus cette exploration locale de forme explicitement demandée ; elle ne vaut toujours pas remplacement du composant canonique ou acceptation des pixels. Références/baselines historiques conservées ; source métier inchangée. Aucune intégration ni commit UI avant acceptation.
