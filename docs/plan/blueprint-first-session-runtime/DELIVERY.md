## Résultat fonctionnel observé

La vraie app Expo Go58, sur un simulateur iOS26.3 dédié et une base jetable,
a consommé des déclarations/observations synthétiques soumises par les vrais
consommateurs. Un snapshot possédé a alimenté le vrai producteur V3 et son
validateur admis ; accord temporel explicite, commande durable, une séance
serveur, sept exercices et quatorze séries de travail initialement non réalisées.
Trois faits typés ont été acquittés. Arrêt du processus, reprise de la même
séance, sortie incomplète et lecture SQLite/serveur ont été vérifiés.

La correction concurrente d'un autre consommateur a provoqué le409 attendu :
version serveur11reps, correction locale10 refusée. Choix explicite de garder
la version serveur, refus conservé RESOLVED sans faux ACK ; nouvelle correction
12reps ensuite acquittée, date initiale et séance clôturée conservées.
A→B : partition B sans séance, rencontre ou opérations de A ; plan propre à B
avec réglage31, distinct du17 de A. Ces nombres sont des entrées de test,
jamais des constantes d'initialisation ou des faits personnels.

Le pilote initial s'ouvre sans sept réglages ni cadence/budgets complets. Il
reste distinct du plan limité qui exige sept réalisations qualifiées. Le
réglage observé n'est pas une charge optimale ; le RIR reste une cible subjective.
La durée demeure UNKNOWN, sans promesse de terminer dans le budget.

## Code réalisé

- Sept tables serveur et une table SQLite locale, indexes/FK propriétaires,
  migration additive sans seed ACTIVE, sans DDL PLAN implicite à startup.
- Ledger append-only, provenance/manques, révision transactionnelle partagée
  avec les préférences historiques ; snapshots et évaluations immuables,
  accord enfant, commandes/reçus/récupération possédés.
- Bundle SCI privé vérifié, sous-processus isolé et vrais chargeurs/producteurs/
  validateurs. Test HTTP hermétique hors checkout ; aucun factory READY servi.
- Création atomique, clés/digests, tombstone cancel, unicité permanente du premier
  handoff ; garde persistée partagée avec starts historiques.
- Prescription exacte sans template/warmups ajoutés ; faits SetLog canoniques
  et réglages/contextes typés, corrections CAS, export JSON fidèle. Dérivés
  incompatibles NON_EVALUABLE ou refusés, pas de score80/NULL→0.
- Clients/contrôleur V3 parallèles, auth et générations, vraie SQLite/outbox,
  progression/reprise/journal/correction et résolution explicite des refus.
  V1, FirstPlanClient et ses pins restent inchangés.
- Compte/préférences et MISSION conservés ; nouveaux rendus dans le board
  [UI](UI_REVIEW.md), pixels acceptés avant commit UI («Valider ces pixels PLAN contrôlés»).
